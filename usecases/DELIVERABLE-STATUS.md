# DELIVERABLE STATUS — read before sending anything to a customer

**As of 2026-08-03, every `.rvt` file in this repository is an INTERNAL
ENGINEERING PROOF, not a customer deliverable.**

The `.rvt` files generated to date (the electrical-room files, the
`experiments/` variants) were authored by CLONING content from Autodesk's
sample projects — Autodesk-authored template projects and Autodesk-authored
families (wall types, panelboard/transformer families, etc.). They exist to
prove the writer works. The content-sourcing strategy
(`docs/product/content-strategy.md`) is explicit that we do NOT ship or embed
third-party-authored content we lack rights to — including Autodesk sample
content.

## Cutover gate (must ALL be true before any generated .rvt is a deliverable)
1. The base document is OUR OWN (genesis / a document we synthesized), not an
   Autodesk sample project.
2. Every family/type in the file is either (a) generated by us from lawful
   FACTS, (b) supplied by / downloaded by the CUSTOMER under the vendor's own
   terms (download-on-demand), or (c) from a source whose terms are
   documented as permitting this exact use.
3. `tools/rvt_validate.py` reports zero errors.
4. A content-provenance manifest is emitted with the file (source + license
   basis per family).

Until then: label = NOT FOR DELIVERY. The IFC/documentation outputs (which
carry only geometry and data WE generate from the customer's own design) are
NOT affected by this gate.
