# lazy-ifc-import — stop taxing prompt-only jobs with the ifcopenshell import (issue #6)

**Stream:** lazy-ifc-import (engineer session for #6; Refs steer #108 — plugin/skill-path
latency is first-class, "done" only with a measured before/after from a bare surface).
**Date:** 2026-08-09. **Territory:** `src/rvt/ifc/intent.py` (import block + `_load_ifcos()`),
one new test, `tests/ci_shard.txt`, this record. Plugin mirror regenerated by
`tools/sync_plugin.py` (1 file: `plugin/lib/src/rvt/ifc/intent.py`).

## What was built

`rvt.ifc.intent` used to do a guarded **module-level** `import ifcopenshell` +
`ifcopenshell.util.element`. The whole front door imports that module
(`rvt.frontdoor` → `rvt.frontdoor.intent` → `rvt.ifc.intent`), so on any box where the real
190 MB library is installed EVERY author/edit/convert process paid its import — and, measured
here for the first time, ifcopenshell 0.8.5 drags **numpy, shapely and lark** in with it
(`ifcopenshell.sql` → numpy; `ifcopenshell.util.shape` → shapely) — prompt-only jobs included.

The fix (equivalent to perf-deps P1, with one correctness difference):

* `ifcopenshell` and `_ue` are now `rvt._lazyimp.lazy_import` proxies (the same mechanism the
  perf-coldstart stream used for numpy): the real import happens on **first attribute access**
  and rebinds the module global to the real module, so steady state has zero indirection.
* `_load_ifcos()` forces the deferred import and returns `False` when neither the real library
  nor the bundled steplite shim is importable; `resolve_intent()` gates on it and raises the same
  `IntentError("ifcopenshell is required to read IFC")` as before.
* Why proxies and not the record's `ifcopenshell = None` + helper: `_psets()` (called directly by
  `tests/test_ifc_intent.py` and usable by any importer) does `_ue.get_psets(...)` inside a broad
  `except Exception`; with a plain `None` global a caller that had not gone through
  `resolve_intent()` first would silently get `{}`. The proxy makes every call site self-loading;
  call sites are otherwise unchanged.
* Backend selection is untouched: ordinary import resolution still picks the real library or the
  shim; `RVT_STEPLITE_FORCE=1` still forces steplite; `product_facts.py` was already lazy.
* `import ifcopenshell` was the **only** eager heavy import left on the prompt path
  (`-X importtime` before/after below; grep of `src/rvt` confirms no other module-level
  ifcopenshell/numpy/shapely import).

Regression gate: `tests/test_lazy_ifc_import.py` (2 tests, 0.5 s, added to `tests/ci_shard.txt`).
It imports the whole front door + validator + `rvt.ifc.intent` + `product_facts` and parses a
prompt in a subprocess whose `sys.path` carries the steplite shim dir (what `ensure_engine`
appends on a bare surface), asserts `ifcopenshell`/`numpy`/`shapely` are absent from
`sys.modules`, then proves `_load_ifcos()` resolves and rebinds (positive control — so the gate
is meaningful on CI where the real library is absent). Second test: with every `ifcopenshell`
import blocked, `resolve_intent` still refuses with `IntentError`. Both tests **fail on the old
code** (checked by stashing the fix) and pass on the new.

## Findings worth keeping

1. **ifcopenshell 0.8.5's import is not 0.3 s of "itself"** — it eagerly imports numpy
   (`ifcopenshell.sql`), shapely (`util.shape` via `util.element` → `util.representation`) and
   lark (`util.mvd_info`): 17 + 88 + 39 + 23 modules. Any future module-level
   `import ifcopenshell.util.*` re-imports all of that; the regression test now catches it.
2. After the fix the prompt job's whole-process import bill is ~200 ms, of which numpy (49–63 ms,
   pulled lazily by the validation gate's ECC math) is the single largest item; the rest is many
   small stdlib/rvt modules (`xml.sax.saxutils` 18–30 ms and `urllib.request`/`http.client`
   14–29 ms on the bare surface stand out as stdlib weight the prompt path probably does not need
   at all — worth one look).
3. **The prompt job is build-dominated**: ~19–21 s wall for the 6-panel room on this box
   (bench's 1-panel prompt: ~5 s), imports are now ~1% of it. The next latency win on this
   path is inside the build (famgen ×6 + load + place + the in-process self-check validation),
   which needs a profile, not an import diet. Filed as a follow-up with these numbers.
4. `surface_bench` on an image whose `/usr/bin/python3` lacks numpy reports `author-ifc` as
   FAIL although the product behaves as designed (honest exit 3 naming the missing extra) —
   the harness should call that BLOCKED so a real regression is distinguishable. Follow-up.
