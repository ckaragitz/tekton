## Why

After #677 three callers normalised the same argument right before handing it to the same function:
`read_streams` (`read_entries(os.fspath(path))`), `rewrite_entries` (`src, dst = os.fspath(src), os.fspath(dst)`) and
`tests/conftest.twin_partition_entry` (`read_entries(os.fspath(src))`); two tests spelled it too
(`test_cfb_rewrite_entries._directory`: `catalog(os.fspath(path), …)`, `test_rewrite_entries_646`: `read_entries(str(…))`).
Three normalisations of one argument to one function say the function should own it.

## What landed

1. **`src/rvt/roundtrip.py`** (the only engine file; `cfb_writer.py` -- the stdlib-only leaf -- defines `CfbEntry` /
   `write_cfb`, not the readers, and is untouched):
   * `read_entries(path: str | os.PathLike[str], *, with_data=True)` -- `olefile.OleFileIO(os.fspath(path))`, the one
     touchpoint; docstring says `str` or any `os.PathLike`, normalised there once.
   * `catalog(path: str | os.PathLike[str], *, hash_streams=True)` -- `path = os.fspath(path)` first (it feeds
     `_read_header_fields`' `open`, `olefile.OleFileIO` and the `"file": os.path.abspath(path)` field, which therefore stays
     a `str`); docstring says so.
   * `read_streams` -- `read_entries(path)`, no wrapping.
   * `rewrite_entries` -- **`dst = os.fspath(dst)` kept** (it is the return value, documented "as `str`", and
     `test_cfb_rewrite_entries` pins `out == str(tmp_path / …)`); **`src`'s dropped**: its three uses are `read_entries(src)`
     (now normalises itself), `os.path.samefile(src, dst)` (takes `PathLike`) and the `KeyError` text, which interpolates
     `os.fspath(src)` at the raise (review round 1, so an exotic `PathLike` whose `__str__` is not its `__fspath__` still names
     its *path*); the new module pins that the message for a `Path` src and for a bare-`__fspath__` src equal the `str` src's,
     args for args.
   * `roundtrip(in_path, out_path)`, `verify_pair`, `byte_diff_report`, `print_params` -- untouched: none of them wrapped for
     `read_entries`, and widening their own annotations is not this issue.
   Plugin mirror `plugin/lib/src/rvt/roundtrip.py` regenerated by `tools/sync_plugin.py` (the only plugin delta).
2. **Callers.** `src/` and `tools/`: no caller outside `roundtrip.py` wrapped for `read_entries` / `catalog` (`git grep` below --
   every `tools/*.py` call is already `read_entries(path)`); `src/rvt/frontdoor/input_release.py:92`'s `open_rvt(os.fspath(path))`
   is for `open_rvt`, not `read_entries`, and frontdoor is not this session's territory anyway -- left. `tests/`: 
   `conftest.twin_partition_entry` → `read_entries(src)`; `test_cfb_rewrite_entries._directory` → `catalog(path, …)` (its
   `import os` had no other user and went with it); `test_rewrite_entries_646.py:39` → `read_entries(tmp_path / "like1.rvt")`.
   All three are adoption only -- no assertion changed, collect ids identical (below). `conftest.partition_of`'s
   `open_rvt(os.fspath(path))` and `test_rvt_job_scrub_656.py:47`'s are `open_rvt` calls -- a different function, left.
3. **`tests/test_read_entries_pathlike_693.py`** (new, 15 ids) + drop-in `tests/ci_shard.d/693-read-entries-pathlike.txt`, on the
   `pin` fixture (fresh-clone safe): `read_entries(spell(pin))` == `read_entries(pin)` field by field (`dataclasses.astuple`) and
   the `with_data=False` pass too, for `spell` ∈ {`pathlib.Path`, a bare object with only `__fspath__`}; `catalog` likewise
   (`entries`, `header`, and `file` still `== os.path.abspath(pin)`, a `str`); `read_entries` / `catalog` / `read_streams` of
   `5` (an `int`), `5.0` and `object()` raise `TypeError` (type pinned, not text) -- **the `int` rows are the ones that go red on a
   revert** (review round 1): with `main`'s `roundtrip.py` swapped in, the module is **2 failed / 13 passed**, `[int-read_entries]`
   and `[int-catalog]` dying `OSError: [Errno 9] Bad file descriptor` inside `olefile.py:1231` / `_read_header_fields`' `open` --
   i.e. `open(5, "rb")` really did treat the argument as a live file descriptor (and under pytest's default capture that read
   garbled the runner's own output); `[int-read_streams]` stayed green on `main` only because `main`'s `read_streams` still
   `os.fspath`-ed one level up. `float` / `object()` were `TypeError` from `open` on `main` already (kept as the type contract, not
   as revert detectors). `rewrite_entries(Path(pin), …)` gives the same bytes as the `str` src, returns `str`, and its `KeyError`
   for a missing stream has the same `args` for a `str`, a `Path` and a bare-`__fspath__` src (and names the pin), nothing written;
   `conftest.twin_partition_entry(Path(pin))` == the `str` one. New module rather than rows in `tests/test_read_streams_677.py` so
   every touched test file's collect-id diff is empty.

Honest note on what the change *is*: with `olefile>=0.47` (the pinned floor) `OleFileIO(filename)` already falls through to
`open(filename, mode)` for anything that is not file-like or long `bytes`, and `open` / `os.path.abspath` take `PathLike` -- so a
`pathlib.Path` reached the bytes before this PR too (that is how #677's `read_streams(Path(pin))` row was green with the wrapper one
level up). What moves is the *contract*: the annotation and docstring now promise it, the normalisation has one home instead of
three call sites, and a non-path (`5`, `5.0`) is a `TypeError` at our boundary rather than whatever `open(5, "rb")` does with a
file descriptor.
