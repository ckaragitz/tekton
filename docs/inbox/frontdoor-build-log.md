`src/rvt/frontdoor/manifest.py`, `tests/test_frontdoor.py`, this record (`src/rvt/frontdoor/__init__.py`

— the human summary already prints every `manifest_paths` key, so `build.log` shows up there for free.

## The gap (measured 2026-08-10, fresh cloud clone, `main` @ e54f13f)

`build.py` ran the stage chain under `redirect_stdout(io.StringIO())` whenever `quiet` (the default
for `frontdoor.py --json`, hence for the plugin's `go author`), stored the text in `BuildResult.log`,
and nothing ever wrote it out. On the 6-panel room that is **17 `[ifc_intent]` lines / 2,172 B** of
per-family / per-stage progress (`F  PP-1 -> … validate=VALID`, `L  6/6 families loaded in 1 host
pass(es)`, wall / equipment / circuit lines) dropped on every JSON-mode build.

## What was built

* `src/rvt/frontdoor/build.py` — `_stage_stdout(res, out_dir, quiet)`: the router's `route.log`
  shape (#188 / #330) copied exactly. When `quiet`, `<out_dir>/build.log` is opened **at call time,
  before the stage `try`** (`buffering=1`, `encoding="utf-8", errors="backslashreplace"`), the stage
  chain runs under `redirect_stdout` straight into it (tail-able; a crashed build keeps the lines
  printed before the crash — verified with a synthetic raising stage: caller stdout `''`, `build.log`
  = the pre-crash line, `errors` = `build crashed: …`), and `BuildResult.build_log` names the path
  (also in `as_json()["build_log"]`). An `OSError` on open degrades to an unlogged run: `io.StringIO()`
  sink + a **degradation** note `build.log not writable (…); stage output not logged` — deliberately
  `res.degradations`, not `res.errors`, because on the front door any `build.errors` entry rolls the
  manifest status up to `FAILED (…)` (`manifest._rollup_status`) and logging can never cost a delivery
  (hard rule 1); the router could use `errors` because its status is set by the stage, not rolled up.
  Not `quiet` (`--verbose`): `nullcontext()` — live on stdout, no file, exactly as before. The dead
  `BuildResult.log: str` field (no consumer anywhere — grep) is replaced by `build_log: Optional[str]`.
* `src/rvt/frontdoor/manifest.py` — `manifest.json` names it at `build.log` (`m["build"]["log"]`,
  repo-relative like `families_dir`; `null` on `--verbose` / degraded runs); `MANIFEST.md` gets one
  line `stage log (per-family / per-stage progress): <path>` after the degradations/errors; and
  `write_manifest` returns `{"json", "md", "build.log"}` — the third key only when `build.log` is set —
  so **every** create route's `AuthorResult.manifest_paths` (= the `--json` result's `manifest` block,
  mirroring the router's `manifest["route.log"]`) names it from one place, `tools/frontdoor.py`'s
  human summary lists it (`manifest : build.log -> …`) with no hot-file edit, and it is never a role
  in `files`. `src/rvt/frontdoor/__init__.py` ends up untouched.
* `tests/test_frontdoor.py` §8b — four cases: `test_quiet_build_writes_its_stage_log_and_names_it`
  (rides the existing module-scoped `identity_job` build, so it costs nothing: path ==
  `<out>/build.log`, contains `[ifc_intent] F  `, named in `manifest.json` + `MANIFEST.md`, absent
  from `files`); `test_cli_json_is_one_document_on_stdout_and_nothing_on_stderr` (subprocess
  `frontdoor.py author --json` on the pinned base, ~3.5 s: `stderr == ""`, `json.loads(stdout)`
  succeeds, no `[ifc_intent]` on stdout, `doc["manifest"]["build.log"]` is `<out>/build.log`);
  `test_verbose_build_stays_live_on_stdout_and_writes_no_log` (unit, ms: `quiet=False` → progress on
  capsys stdout, no file, `build_log`/`as_json()["build_log"]` `None`; `write_manifest` names the key
  only when the log is set); `test_unwritable_out_dir_degrades_to_an_unlogged_build_not_a_crash`
  (`chmod 0555`, self-skips via `os.access` when root keeps the dir writable; as uid `nobody`: 1
  passed — stage ran, `errors == []`, degradation note present, nothing on caller stdout, no file).
  `tests/test_frontdoor.py` is already in the CI shard, so no `ci_shard.d` drop-in is needed.
* `/simplify` pass (4 reviewers): folded the first draft's `__init__._name_build_log` + two call sites
  into `write_manifest` (one place, all routes); dropped a one-consumer `BUILD_LOG` constant for the
  router's literal idiom; trimmed the CLI test to the stdout/stderr contract (the fixture test owns
  the content asserts) and turned the verbose case from a 2.5 s build into a unit test. Skipped →
  follow-ups below.

## Findings

* The captured text is byte-for-byte what `--verbose` prints (2,172 B both ways) — the capture is
  `sys.stdout`-level, and every stage line on this path comes from `tools/ifc_intent._log` → `print`.
  A stage that shells out would have to capture its child itself (same caveat as the router; none does
  on the create routes today).
* The human (non-`--json`, non-`--verbose`) path was also `quiet=True` and also dropped the log; it now
  gets `build.log` too and `_print_summary` lists it as `manifest : build.log -> …` with no CLI change.
* `go author --json` from a bare unzip re-wraps the job's stdout into `result`; with the front door's
  stdout already one document the `go` envelope is unchanged except for the extra `manifest` key —
  verified above (bare unzip row).
* `/verify` (this head): the DONE command → rc 0, stdout 1,700 B = one JSON, stderr 0 B, no
  `[ifc_intent]` on stdout, `out/x/build.log` 2,172 B / 17 lines, named in `result.manifest`,
  `manifest.json` (`build.log = out/x/build.log`) and `MANIFEST.md:79`; `out/x/prompt_room.rvt`
  → `tools/rvt_validate.py` `ok: true`, 0 errors (validates — not a load claim); `--verbose` → 17
  lines live on stdout, stderr 0 B, no `build.log`; `--target-version 2025 --json` → one JSON,
  stderr 0 B, `manifest` keys `build.log, json, md`, 17 lines, output validates 0 errors under 2025.

## Open questions / follow-ups (filed as task issues, `Refs #312`)

* **One `stage_stdout` for all three front-door routes.** `build._stage_stdout` is a deliberate
  near-copy of `router._stage_stdout` (#188/#330; `router.py` was outside this territory), and
  `edit.py:375-384` is the third copy of the *old* pattern (quiet → `StringIO` → text stuffed into
  `run["log"]` → `manifest.edit.log_tail[-2000:]`), so after this PR `manifest.build.log` is a *path*
  while `manifest.edit.log_tail` is *content*. Hoist to a small `src/rvt/frontdoor/stagelog.py`
  (`stage_stdout(out_dir, name, *, on_open, on_degrade)`), make router/build three-line wrappers, give
  the edit route `<out>/edit.log` named the same way — and converge the router's degrade note onto a
  non-fatal channel (its `errors` note is harmless only because the router's status is stage-set, not
  rolled up). Importing the router's helper into `build.py` was rejected: wrong layer direction (the
  build would eagerly load the 1,600-line orchestrator on every prompt/IFC job — O10).
* `tests/test_router.py::test_frontdoor_json_stdout_stays_one_document` (#188's regression guard) is
  now a weaker twin of `test_cli_json_is_one_document_on_stdout_and_nothing_on_stderr`; both files
  are in the shard, so CI pays ~3.5 s twice for one contract. Fold/delete in the hoist PR (router
  test file was out of territory here).
