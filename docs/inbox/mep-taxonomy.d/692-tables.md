## Decisions and the lines held

- **No numeric category id was invented.** Rows use only keys `skeleton._resolve_category` already
  knows; kinds whose true category it lacks (air terminals, sprinklers, plumbing equipment, duct
  and pipe runs) are `NOT_YET` entries with the reason, not rows under a wrong category (#692:
  "never a wrong category"). Water heaters sit under Mechanical Equipment with a note that Revit
  2022+ also offers Plumbing Equipment.
- **No dimensions anywhere.** Neither row type has a numeric field (a test pins it); line labels
  name product families, never sizes or ratings as data. Trade names are used only where they are
  common knowledge (Pow-R-Line, NQ/NF/I-Line, QED-2, Altivar, SINAMICS, BLT, LDN6, Metalux, Halo,
  TrueAlarm, e-1510, …); elsewhere the label is a plain description of the line.
- **`facts_held` is computed truth, not an opinion**: it is the presence of a catalog key, and
  `check()` loads it. A vendor we can name but hold nothing for says exactly that
  (`describe("trane", kind="chiller")` → "no sourced member data is held, so a family is generated
  at nominal/standard dimensions and says so; supply a spec sheet for true dimensions").
- **#674 is probed, never imported.** `archetype_registry()` tries `rvt.famgen.archetypes`
  (`ARCHETYPES` dict or `keys()`), returns `None` when absent; archetype rows then report
  "registry … is not on this build" and `check()` stays clean. The five registry keys and their
  categories were read from PR #674's head (`f9743c7`) so the rows agree with it the day it merges:
  cable_tray → Cable Tray Fittings (a loadable ladder-tray *section*, per steer #591 — a routed run
  stays Revit's system family), conduit → Conduit Fittings, wireway → Electrical Equipment,
  strut_channel → Generic Models, junction_box → Electrical Fixtures.
- Catalog kinds keep priority over archetypes (S-2026-08-10-e): `builder_available` consults the
  builder + held facts first; the archetype key on `junction_box` is the fallback, not the default.

## What this does NOT do yet (slice 2, DONE 3 and 5)

The prompt resolver (`src/rvt/frontdoor/prompt_intent.py` / `router.py`) and the #684 interview do
not read these tables yet; today they still carry their own product lists. Slice 2 replaces those
lists with `taxonomy.resolve()` / `vendors.lines_for_kind()` and relays `describe()["line"]` for a
kind that is placed but not built. Filed as the follow-up on #692 (same issue, next PR).

## Open questions

- Discipline of borderline kinds (water heater: plumbing vs mechanical; fire pump: fire
  protection) is a presentation choice; the category is what Revit cares about and is fixed.
- Whether `NOT_YET` categories should be added to the resolver as `[INFERRED]` ids (#516's
  pattern) is #516's call, not this table's — the taxonomy will follow the resolver.
