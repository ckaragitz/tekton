## eng #373 — 2026-08-10 (fresh cloud clone, no `samples/`, `main` @ 6d5b82b)

### The gap

Three copies of one idiom, two semantics. `router.py::_stage_stdout` (#188/#330) and `build.py::_stage_stdout`
(#312, a deliberate copy) each opened `<out>/{route,build}.log` line-buffered utf-8/backslashreplace, caught
`OSError` into an in-memory sink + a note (`res.errors` for the router, `res.degradations` for the build), and
named the path. `edit.py::run_edit` still ran the job runner under `redirect_stdout(io.StringIO())` and stuffed
the text into `run["log"]` → `manifest.edit.log_tail[-2000:]` — so `manifest.build.log` was a *path* and
`manifest.edit.log_tail` was *content*, and a quiet edit wrote no log file at all. And the #374 review's edge:
the build's log opens **after** `standalone.forbid_research_inputs` is armed, whose audit hook raises
`StandaloneError(RuntimeError)` — not `OSError` — from inside `open()`, so `--out …/samples/x --json` gave
**rc 1 + a 1,492 B traceback ending `StandaloneError: … samples/x/build.log`, 0 B on stdout, no manifest**
(reproduced on `main` @ 6d5b82b before touching anything).

### What was built

* `src/rvt/frontdoor/stagelog.py` (66 lines, stdlib only, imports nothing from the rest of `rvt.frontdoor`) —
  `stage_stdout(out_dir, name, *, quiet, on_open=None, on_degrade=None) -> ContextManager`: not quiet →
  `nullcontext()`; quiet → `open(<out_dir>/<name>, "w", buffering=1, encoding="utf-8", errors="backslashreplace")`
  **at call time**, `on_open(path)`, `redirect_stdout` into it for the block; any exception from `open()`
  (`OSError`, or whatever an audit hook raises — the tripwire's `StandaloneError`) → `on_degrade("<name> not
  writable (<Exc>: …); stage output not logged")` + an `io.StringIO()` sink. The `except` is deliberately
  `Exception`, not `(OSError, StandaloneError)`: importing `standalone` here would drag the front door into a
  leaf module (`tools/rvt_job.py` wants this helper without `rvt.frontdoor` on its hot path, see follow-ups), and
  the law is about the *log*, not about which layer refused it — an observer that cannot open never costs the run.
* `router.py::_stage_stdout` / `build.py::_stage_stdout` are now 3-line wrappers (`on_open` = name the path where
  each result keeps it, `on_degrade` = the result's non-fatal list). Behaviour unchanged for the build. **Router:
  the unwritable-dir note moved from `res.errors` to `res.caveats`** — the router's existing non-fatal channel
  (matrix cell caveats and every absorbed `build.degradations` entry already land there, `tools/route.py run`
  prints them as `caveat :` lines); `errors` stays for stage failures. `tests/test_router.py::test_quiet_route_into_readonly_dir_still_runs_its_stage`
  adjusted accordingly (asserts the caveat, and that no `route.log`/`route crashed` line is in `errors`; the
  pre-existing `route manifest write failed: PermissionError` error for a wholly read-only dir is untouched).
  `build.py` drops its now-unused `import io`.
* `edit.py::run_edit(quiet=True)` runs `J.main(argv)` under `stage_stdout(out_dir, "edit.log", …)` and returns
  `log_path` + `degradations` instead of `log` (content). `manifest.edit` gains `log` (the path, `_relp`'d like
  `build.log`) and `degradations` (the one note when the log could not open, else `[]`); **`log_tail` is gone** —
  the DONE allowed keeping it one release as a view of the file, `/simplify` found no consumer of it anywhere in
  `src/ tools/ plugin/ skills/` (only this PR's own tests), and keeping it meant a whole-file read at manifest time plus
  up to 2 KB of the log duplicated into every `manifest.json` (10,092 B → 8,368 B on the pinned-base edit); the path is
  the contract now, exactly as for the build. `write_manifest` names the log beside `json` / `md` for whichever of
  `build` / `edit` recorded one, keyed by **the recorded path's own basename** (no second literal `"edit.log"` in
  `manifest.py` to drift from the one passed to `stage_stdout`); `MANIFEST.md`'s Edit section prints
  `- **degradation**: …` lines and `- job log (plan / commit / gate progress): <path>`.
* `tests/test_router.py::test_frontdoor_json_stdout_stays_one_document` deleted (the weaker twin of
  `tests/test_frontdoor.py::test_cli_json_is_one_document_on_stdout_and_nothing_on_stderr`; ~3.5 s no longer paid twice
  in the shard).
* New tests: `tests/test_stagelog.py` (5: verbose null context; quiet streams into the named file, opened at call
  time, tail-able mid-block, a lone surrogate escaped not raised; read-only dir → block runs, ONE note, no file,
  nothing on stdout; **tripwire armed + `…/samples/x` → identical degradation with `StandaloneError` in the note**;
  callbacks optional / missing dir silent) — fresh-clone safe, in the shard via `tests/ci_shard.d/373-stagelog.txt`.
  `tests/test_frontdoor.py` §8c (3): quiet edit on the pinned 2025 base writes `edit.log`, `manifest_paths["edit.log"]`,
  `manifest.edit.{log,degradations}` (and no `log_tail` key), `--verbose` writes none and leaks progress live as before; an
  unopenable `edit.log` (squatted by a directory — an `OSError` under any uid, so it runs as root too) → edit
  **delivered**, ONE degradation, no log named, stdout clean; `--out <tmp>/samples/x --json` at the CLI → rc 3, stderr
  `""`, ONE JSON, manifest written, no traceback — the envelope only; today that JSON says `NO-OUTPUT` with a
  `build.log not writable (StandaloneError…` degradation, and whether it should instead deliver is #425 (below).
