**Audit hardening (same module).** `verify_evidence()` unchanged in contract;
new `audit()` classifies its output: HARD problems (a `certified:` ref not in
the ledger, a cited test/worked/record path missing, malformed refs, unknown
stages, chains pointing at missing cells) vs certified probe *binaries* absent
on a fresh clone (git-ignored `experiments/**/*.rvt`; the ledger certifies
them, rule 4). On a checkout that carries the binaries an absent one is still
hard (the next round's byte-identical control needs it). Consequence: the
honesty gate now RUNS on fresh clones and CI instead of skipping wholesale
(before: `test_evidence_self_audit_is_clean` skipped here; `route.py matrix`
exited 3 with "30 citations FAILED"). `render_text()` is the one printer both
CLIs use.

**Router (`src/rvt/frontdoor/router.py`).** New impls compose the convert
routes as-is and fold their manifests into the RouteResult (files, stamps,
caveats-after-delivery, gate verdicts as labels — `_absorb_convert_record` /
`_convert_status`: delivered + gates VALID → OK; delivered with a red gate →
"DELIVERED WITH A RED GATE (…)" and still ok=True per the deliverable rule;
nothing delivered → FAILED): `_r_rvt_to_ifc`, `_r_extract_family` (no selector
+ one family → extracts it; several → `NEEDS-A-SELECTOR` + the list in one line
+ `families.json` delivered; none → clear line), `_r_rfa_modify` (famspec
refused with the line: generate first), `_r_add_into_rvt`, `_r_ifc_merge_into_rvt`,
and the reload lane `_reload_rfa` inside `_r_rfa_load`. Two behaviour points
worth review:

* **edit vs add is decided on SHAPE, without the file** (`_edit_shaped`:
  ops.json / inline JSON / a clause of the edit grammar ⇒ edit). Before, a
  grammar clause whose *name* did not resolve (`move DP-1 to 3,4` on a file
  with no DP-1) raised `EditParseError` and fell into the authoring branch —
  which, with `add_to_project` wired, would have ADDED a DP-1 (observed live
  during this stream before the fix). Now it stays an edit and the edit
  pipeline reports the unresolved name.
* **default load host = the pinned certified genesis base** (`resolve_base()`:
  repo copy or plugin-bundled, hash-verified) instead of
  `samples/rstbasicsampleproject.rvt` — a sample can never be a product
  default (rule 3) and is absent on every fresh clone/plugin. `--rvt` still
  loads into the user's project. A missing pin is a FAILED status + line,
  never a traceback.

The reload lane's honest limit is spelled out in the line it returns: a
STANDALONE-BORN .rfa (any Revit-saved family, and our own `start_id=1000`
deliverables) has ids below any host watermark; the component loader splices
records verbatim and cannot renumber; the schema-typed id-remap + famload lane
that DOES load any Revit-born .rfa is certified (T2a) but lives in
`tools/rft_probe.py` — product wiring filed as **#99**.

**CLI (`tools/route.py`).** `run` gains `--family`, `--level`, `--at X Y`,
`--offset DX DY`, `--no-roundtrip`; `matrix` delegates to `render_text()`
(exit 3 only on HARD audit problems; `--json` carries `audit`).

**Hot file (`tools/frontdoor.py`) — the patch, re-derived.**

## 3. Findings (each cost a re-think; recorded so nobody repeats it)

1. **`worked:` citations must point at TRACKED files.** convert-a §6b proposed
   `worked:experiments/convert/extract-family/DP1_reextracted.rfa` — a
   git-ignored binary; cited that way the audit fails on every fresh clone and
   in CI (only the `certified:` class has a fresh-clone tolerance, and only
   because the ledger backs it). Cite the `.manifest.json` / `.load.json` /
   `.ifc` beside the binary instead. `verify_evidence()` now catches this
   everywhere because the test no longer skips.
2. **The original frontdoor patch was plugin-hostile** (imports `route.py`,
   which the bundle does not ship). Any future front-door verb must delegate
   into `plugin/lib/src` modules, not sibling tools.
3. **Edit-vs-add must be decided on shape**, or an unresolved edit name turns
   into an addition once an add route exists (see §1).
4. **The famspec (downlight) lane is owner-machine-only today**: `famfrom_ifc`
   emits its .rfa on `famdoc_adoc.TEMPLATE_DONOR` (the vendor .rfa in the
   git-ignored corpus, read for structure); on a fresh clone `route --rfa
   '{"kind":"downlight"}'` fails at `rfa-emit` with "family container source
   not found". Already tracked by **#94**; the matrix caveat says so; the test
   is gated `needs_famcontainer` instead of the old `needs_rst`.
5. **prompt_intent double-counts named equipment** ("one 100 A lighting panel
   LP-1" → LP-1 *and* LP-2; "named LP-1" → two items BOTH tagged LP-1) — found
   while sizing the e2e fixture; filed **#101** (frontdoor territory, not this
   stream's files). The fixture prompt avoids tags.
6. **Reload watermark law, precisely**: an extracted family reloads into a
   host whose watermark is BELOW its ids — the pinned base always qualifies;
   the project it came from (already grown past those ids) refuses by name.
   Stated in `_RFA_INPUT` (b) and tested.
7. `.claude/skills/verify/SKILL.md` calls `out/verify` "git-ignored" — it is
   not (`git check-ignore` matches nothing under `out/`; only `experiments/out/`
   and `tests/out/` are ignored). Harmless here (files are staged explicitly,
   `out/` deleted before push) but a `git add -A` habit would commit built
   `.rvt` binaries; worth one `.gitignore` line by whoever next touches it.
8. H8B (our famdoc via famload on the pristine rst host) FAILED at verdict
   #39, so this stream does NOT repeat KNOWLEDGE's inference that
   add-into-user-projects "rides the passing cell"; the INTO caveat says
   plainly: expect the audit to reject added equipment until the open cell
   closes; a viewer round for the INTO artifacts is filed as **#103**.
