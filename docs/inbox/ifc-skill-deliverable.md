## 1. What changed (wording only — no restructure, description untouched)

* **:29 glossary row** `APS Design Automation` → `tekton-author`: the sibling
  skill that builds a native `.rvt` for a named release from a prompt or an
  `.ifc` in one call (`_bootstrap.py go author --ifc FILE --target-version
  YEAR`), no Revit / no Autodesk cloud service, always delivered and honestly
  stamped (`PROOF-ONLY` + named caveats until certified); points at 6.4.
* **§1 Tier 2 prose**: Tier 2 = a native `.rvt`, and this plugin builds it
  itself via **tekton-author** for the user's release with an honest
  `PROOF-ONLY` stamp; the user gets the `.rvt` AND the Tier 1 IFC (links in
  any Revit) AND the Tier 2 handoff package. "Never claim Tier 2 from IFC"
  kept verbatim.
* **§2 route row** (`real families, connectors, circuits, or a .rvt`): ask the
  Revit version FIRST (6.4), hand the validated `.ifc` to tekton-author in one
  call (`python <plugin>/skills/tekton-author/scripts/_bootstrap.py go author
  --ifc FILE --target-version YEAR --out out/rvt`), relay its honest
  status/stamps; ALSO deliver the Tier 1 IFC as the version-agnostic
  addition, never a substitute, + the handoff package.
* **Rule 8**: `IFC is version-agnostic; .rvt is not. … For a .rvt, ask the
  user's Revit version first and route to tekton-author (6.4); the IFC ships
  alongside it as the version-agnostic addition — never instead of a
  requested .rvt.`
* **5.4 item 4**: `the APS step` → `the tekton-author .rvt step (6.4)`.
* Troubleshooting row 8.8 unchanged (as the DONE requires); 6.4 unchanged.
