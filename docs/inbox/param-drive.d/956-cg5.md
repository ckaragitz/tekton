# #956 — CG5 corrected to the born law (a nested document labels with its host's shared parameters)

(+ its `plugin/lib` mirror), `tests/test_cg5_956.py`, `tests/ci_shard.d/956-cg5.txt`,

## The problem

Sweeping `check_file` over the 421-family Revit-born reference library — host
documents plus every nested unit (`nested_units` / `check_file(path, unit=u)`)
— left **236 CG5 errors**, all in nested units (host documents: 0). A law that
fires on Autodesk's own output is wrong by definition (the #910 / #953
precedent).

## Census — what the 236 findings flag

The library is a git-ignored development instrument; only counts and field
facts are cited here (no file, parameter or path names). Instrument: 421 files,
4,846 units (421 host + 4,425 nested), 0 read errors; every labelled segment
(`m_ArrSegInfo[i].m_paramId` >= 0) of every `LinearDimString` / `AngularDim`
classified by where its parameter element lives.

**One class, 236 / 236.** Every finding is the *parameter-exists* half of CG5
("labelled with parameter N, which is not in the document"); the *shape* half
(two-witness alignments, one segment per gap) fired 0 times. All 236 are
`LinearDimString`s with 2 witnesses / 1 segment (233 unlocked, 3 locked), in
155 nested units of 58 files, naming 97 distinct (file, parameter) pairs.

| labelled segments, by where the parameter element is | host | nested |
|---|---|---|
| a `ParamElemFamily` in the dimension's own unit | 5,491 | 21,691 |
| a `ParamElemExternal` (shared parameter) in its own unit | 292 | **0** |
| not in its own unit — a `ParamElemExternal` of the **host** (unit 0) | — | **236** |
| anywhere else / nowhere | 0 | 0 |
| **total** | **5,783** | **21,927** |

Why nested units differ from host documents — field facts:

- **Shared parameters are stored once, in the host document.** 0 of the 4,425
  nested units carries a `ParamElemExternal` of its own; every one of the 236
  missing parameters is a `ParamElemExternal` element of unit 0.
- **Element ids are file-wide.** In every one of the 389 files that carries a
  labelled dimension, no element id of unit 0 recurs in any of its nested
  units, so a nested
  document naming a host id is unambiguous, not a collision.
- **The nested family declares the parameter.** For 236 / 236, the `Family`
  element the dimension's own `m_famId` names (in its unit) lists the
  parameter in `m_familyParams`; the nested unit's family header also lists
  it in `m_parents.m_deletion` (spot-checked). 187 of them are also listed by
  the host's `Family` element whose content document is that unit (the other
  49 were not resolved to a host `Family`; not needed by the law).
- The declaration holds universally: **27,710 / 27,710** born labelled
  segments (host and nested, linear and angular) name a parameter listed in
  `m_familyParams` of the `Family` their `m_famId` names.

## Decision: corrected, not retired

The existence check stays (it catches a genuinely dangling label); its notion
of "in the document" gains the one born form it lacked. In a nested unit a
label may name a `ParamElemExternal` of the **host** document, **provided** the
`Family` the dimension's `m_famId` names lists it in `m_familyParams`.
Nothing looser:

- only `ParamElemExternal` (`HOST_SHARED_PARAM_CLASS`) is borrowed from the
  host — a host `ParamElemFamily` named by a nested label still fails
  (0 born cases);
- a host shared parameter the nested family does not list — or whose
  `m_famId` names no decoded `Family` — fails, with its own message;
- the host document (unit 0) borrows nothing.

Code: `check_graph(..., host_shared_params=)`; `_check_file` passes unit 0's
`ParamElemExternal` ids when judging a nested unit; `Family` joins
`FILE_CLASSES` so the declaration can be read.
