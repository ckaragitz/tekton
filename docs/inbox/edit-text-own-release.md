## 0. The defect, reproduced (fresh cloud clone, `origin/main` @ cd2d5a2, before any change)

`plugin/skills/tekton-native/scripts/rvt_edit_text.py` was a hand-authored
plugin one-off (no `tools/` source): it did `from rvt.writer import
BLOCK_TRL_TAG` at module level and ran `StreamWalker` bare, so on anything but
a 2026 file it died before the edit. Run exactly as the skill documents it, as
nobody (`env -i PATH=/usr/bin:/bin python3` = system Python 3.11.15), on the
three tracked certified bases, edit `--old "GEN Floor Plan" --new "OUR Floor
Plan" --utf16`:

| input | `main` |
|---|---|
| `G_ABPD.rvt` (2026) | `SELF-CHECK PASS`; stamps valid 3102/3102; out sha256 `e2698150…fcc87408` |
| `G_ABPD_2025.rvt` | traceback: `rvt/partitions.py:243 parse_stream_header … ValueError: unexpected Partitions header: v=9 cls=0x391` |
| `G_ABPD_2024.rvt` | traceback, same, `cls=0x37b` |

(So the failure mode on `main` is the walker refusal, not a silent 2026-tag
re-frame — the walk dies first.)

## 1. What was built

* **Moved under `tools/` + sync (the issue's suggestion), because it *is* small
  and mechanical:** `tools/rvt_edit_text.py` is the source; `tools/sync_plugin.py`
  gains one `(_tool("rvt_edit_text.py"), "skills/tekton-native/scripts/rvt_edit_text.py")`
  line beside the other tekton-native script mappings; the plugin copy is now a
  generated byte-identical mirror (`cmp` clean, and `--check` covers it from now
  on). The only non-mechanical part of the move is the import header: the
  `_bootstrap.ensure_rvt()` preamble (plugin-only) became the same three-line
  `HERE/../src` + `HERE/../lib/src` header `tools/rvt_edit.py` uses, so the one
  file runs from the repo (`tools/`) and from the plugin through the documented
  `_bootstrap.py run …` launcher (which puts the bundled engine + vendored
  olefile on the path before `runpy`). Consequence, stated honestly: a *direct*
  `python skills/tekton-native/scripts/rvt_edit_text.py …` from a bare unzip no
  longer self-bootstraps — exactly like its sibling `rvt_edit.py` in the same
  directory; the SKILL documents `_bootstrap.py run` for both, and the script's
  own usage text now says so.
* **The fix itself** (the #70 pattern, nothing reinvented): `main()` parses,
  applies the size-preserving refusal, then enters
  `rvt.frontdoor.release_ctx.enter_host_release(stack, in_path)` **once** around
  the whole body (`_edit()`: walk → edit → re-stamp → re-block → truncate →
  `ecc.frame_stream` → `write_cfb` → read-back self-checks). A native (2026)
  file enters no context; a 2025/2024 file gets its release's framing ordinals +
  codecs; an unauthor-able release prints the refusal sentence as a warning and
  fails honestly at the walker as before. The block trailer is written with
  `rvt.partitions.TRAILER_TAG` **read at call time** (the very constant the
  walker that re-checks the output parses trailers with, and one of the names
  `versions.reading` swaps) — no module-level copy of the 2026 `0x0f21`.
  `StreamWalker` is referenced through the module (`P.StreamWalker`) for the
  same reason. `gzip_member`, `ecc`, `write_cfb`, `read_entries` are
  release-agnostic and unchanged. (Review note, deliberately not taken: a bare
  `versions.reading(path)` would be ~0.1 s lighter per 2025/2024 call than the
  full host context, since this job only needs the framing ordinals — but the
  issue's DONE names `enter_host_release` and parity with `rvt_edit.py` is the
  point: one entry, one refusal sentence, one no-leak guarantee across every
  edit CLI. 0.29 s wall end to end as it is.)
* **Test** `tests/test_edit_text_release.py` (4 tests, fresh-clone safe — the
  certified pins via `conftest.CERTIFIED_YEARS` / `pinned_base`, the tool via
  `conftest.load_tool`): the edit the issue names, a same-length UTF-16 rename
  of a **level** (`"GEN B1 - Basement"` → `"OUR B1 - Basement"`, level 1351691,
  present once in seq-102 of all three bases) on 2024, 2025, then 2026 in one
  process → `SELF-CHECK PASS`, CRC/ECC/walker 0, `detect_release(out) == year`,
  standalone `validate_file` 0 errors with no context active, and the level
  **decodes** with the new name under the file's release (the edit landed in
  the element, stamps consistent); an autouse fixture snapshots the
  `rvt.partitions` framing table + `writer.BLOCK_TRL_TAG` + `active_release()`
  around every test (foreign releases run first, so a leak would break the
  following native edit); plus the length-change refusal (exit 2, nothing
  written). Mirror drift is owned by `sync_plugin.py --check` /
  `tests/test_plugin_sync.py` now that the mapping exists — not re-asserted
  here. In the shard via the drop-in `tests/ci_shard.d/116-edit-text-release.txt`
  (never `ci_shard.txt`).
