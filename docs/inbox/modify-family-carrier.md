## Why
After fba7efb (#336) `famgen/skeleton.new_family_parameter` authors a Text parameter as
`ParamDefString` and an Integer parameter as `ParamDefInt`, both **without** `m_specTypeId`.
`rvt.convert.modify_family.inventory_family` decided the value carrier from the spec id alone, so
`PanelName` (no spec) fell to `m_value` and `set PanelName DP-9` hit `_convert_value`'s numeric
branch: `FamilyEditError: PanelName: cannot read a number from 'DP-9'`. Every prompt+rfa → rfa edit
of a Text parameter on OUR generated families was refused; `tests/test_router.py::test_e2e_prompt_rfa_modify`
was red on `main`.

## What was built
* `_carrier_for_param(def_class, spec)` replaces `_carrier_for_spec(spec)`: the pointer class
  **name** the file's own schema resolved for `m_pParamDef` (`ptr_class` on the decoded pointer —
  no class id is hard-coded) decides first (`…ParamDefString` → `m_str`, `…ParamDefInt` → `m_int`),
  the `m_specTypeId` of a `ParamDefValue` otherwise (`spec.string` / `spec.int64` / doubles — pre-law
  files keep resolving exactly as before).
* Each inventory param now also carries `def_class`; `as_json()` (what `--inventory` prints, for both
  `rvt.convert.modify_family` and `rvt.convert.edit_family`, which reuses `inventory_family`) derives
  a `kind` word from the carrier (`text` / `integer` / `number`), so `PanelName` is listed as **text**
  in so many words. `carrier` stays the one source of truth; `kind` is presentation only.
* Module docstring states the class-first rule; the `m_int` unit note now says "integer parameter"
  (there is no integer *spec* any more).
* `/simplify` pass (4 reviewers) applied: exact `==` on the class name (every `ptr_class` in the engine
  is the bare schema name from `objects.py`; ~40 other sites compare with `==`), `kind` derived not
  stored, no double `str()` coercion, helper docstring cut to two lines, one duplicated test assert
  dropped. Efficiency reviewer: whole new test file 0.43 s, nothing to change. Reuse reviewer: no
  existing class→carrier helper anywhere in `src/rvt`; the test's `_catalog_ok`/`needs_catalog` is a
  fourth copy of a helper that lives only inside other test modules (not `conftest`) — hoisting it is
  a separate cleanup, left alone.
