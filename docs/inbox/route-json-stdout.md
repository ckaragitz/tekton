## What was built

* `src/rvt/frontdoor/router.py` — `route(inputs, output, quiet=True, …)`: when `quiet`, the
  stage chain (`impl(...)`) runs under `_stage_stdout`, a small context manager that
  `redirect_stdout`s **straight into** `<out_dir>/route.log` (line-buffered — no in-memory
  copy, a long route can be `tail -f`'d, a killed/crashed one keeps its progress; verified with
  a synthetic crashing stage: caller stdout 0 B, `route.log` = the line printed before the
  crash, result `FAILED (…)`), and the path rides in `RouteResult.manifest_paths["route.log"]`
  → the `--json` result's `manifest` block tells the caller where the progress went. Non-quiet
  callers are untouched: progress stays live on stdout, no `route.log`.
* `tools/route.py` — `run --json` passes `quiet=True`; `--json` help says so.
* `tests/test_router.py` — three tests in the CLI section:
  `test_cli_run_json_stdout_is_one_document` (in-process `main([... '--json'])` for the
  prompt→rfa cell with the file's established `PANEL_PROMPT`, `json.loads(capsys stdout)` must
  succeed, `[ifc_intent]` absent from stdout and present in the named `route.log`),
  `test_route_without_quiet_still_prints_progress` (human path unchanged),
  `test_frontdoor_json_stdout_stays_one_document` (regression guard: `frontdoor.py author
  --json` on the pinned base parses and carries no `[ifc_intent]`; kept although
  `test_coldstart` parses `go author --json`, because `go` re-wraps the job's stdout and would
  mask a front-door leak — ~2 s warm).
* `/simplify` pass (4 reviewers): streamed log instead of StringIO+`finally`; `build.py`-style
  conditional context; dropped a now-redundant local `import contextlib` in
  `_r_spec_on_rvt_seed`; reused `PANEL_PROMPT` (the `needs_catalog` gate probes exactly its
  facts); de-generalised the one-use CLI loader; trimmed comments. Skipped: folding
  `_r_spec_on_rvt_seed`'s unconditional `job-create.log` (`res.files["job_log"]`) into the
  quiet-only mechanism — it is that cell's delivered evidence, a contract change outside #188.

## Findings

* **Why not `_log → stderr` at the source (the issue's stated preference).** `tools/ifc_intent.py`
  `_log` is the *only* library-level `print(` in that file (lines 1309–1339 are all inside the
  `cmd_*` CLI verbs, unreachable from the router). But it is also what the front door's build
  silences: `src/rvt/frontdoor/build.py:452` captures **stdout only** (`quiet=True`, the default
  for `frontdoor.py --json` and therefore for the plugin's `go author`), and the captured text is
  discarded. Measured on a 6-panel room with `--verbose`: **17 `[ifc_intent]` lines / 2,172 bytes**
  per build. Moving `_log` to stderr would surface those on *every* `go author` / `frontdoor --json`
  call (stderr today: 0 bytes) — a tool-output token-weight regression on the primary skill path,
  which S-2026-08-09-g / #112 make a product requirement — and silencing it again would need a
  `redirect_stderr` in `build.py` (outside this territory) that would also eat genuine warnings.
  So the fix sits where the JSON contract lives: the router owns its stdout when asked for
  `quiet`, exactly the convention `build.py` (quiet log buffer), `edit.py:377`,
  `router._r_spec_on_rvt_seed` (`job-create.log`) and the plugin's `go` dispatch already follow.
  One capture at the choke point also covers leaks `_log → stderr` would not have:
  `skills/tekton-ifc/scripts/generate_ifc.py:830-832` (the spec routes' two lines — a CLI whose
  stdout summary is legitimate when run standalone), and any `print(` in the `rvt.convert` /
  `rvt.ifc` / `rvt.famgen` modules the other cells import (5–12 each; none fired on the cells
  smoked below, but the guard is now structural rather than per-module).
* Every other `print(` on the `--json` path: `tools/route.py` prints only the JSON in `cmd_run`
  when `--json` (usage errors and tracebacks already go to stderr); `router.py` has none.
* Other cells smoked under `--json | json.load` after the change (all ONE JSON, stderr 0 B,
  `route.log` present): prompt→ifc (log 0 B), spec→ifc (244 B), spec→rfa (1,185 B), rvt→ifc on
  the pinned base (0 B), prompt→rvt (0 B — the build's own quiet capture already held it).
* `go route.py run … --json` (a skill calling the router through the one-call dispatch) used to
  rely on `go`'s `rfind("\n{")` fallback and stuff the progress into `go.stdout`; it now gets a
  clean `result` with the progress in the job's `route.log` — same bytes, off the tool output.

## 2026-08-09 — addition by stream #330 (review-nit sweep), not the route-json-stdout voice

The three `_stage_stdout` nits from #313's review are applied in
`src/rvt/frontdoor/router.py`: (1) `route.log` is opened at `_stage_stdout(...)` call
time, *before* `route()` enters its stage `try`; an `OSError` there degrades `quiet` to an
unlogged run (`io.StringIO()` sink + `res.errors` note "route.log not writable (…); stage
output not logged") and the stage still runs, so `--json` is never worse than the human
path; `manifest_paths["route.log"]` is set only when the file actually opened; (2) the log
is opened `encoding="utf-8", errors="backslashreplace"` (cp1252 hardening, O2); (3) the
docstring states the capture is `sys.stdout`-level only — a stage that shells out must
capture its child. New test `test_quiet_route_into_readonly_dir_still_runs_its_stage`
(synthetic stage, no catalog needed; `chmod 0555`, self-skips via `os.access` when root
keeps the dir writable): as uid `nobody` it is 1 passed on this head and 1 failed on the
pre-change router (`ran == []` — stage never ran), i.e. a matched pass/fail pair.
