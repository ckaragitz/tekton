## 4. Identity / footer / version markers

* `BasicFileInfo` format string: **`2024`**, build: **`20230308_1635(x64)`** (the RTM 2024 sample build)
* `Global/History` upgrade-version list: 2024 ends **2662** (190 entries); identical list across 2024/2025/2026: **True** (2025 2662/190, 2026 2662/190).  This is the format-2025.md finding measured from the 2024 side: **2662 is the ADocument schema `version` stamp in all three releases' own schemas, NOT a release marker** -- the document format version froze at 2662 before 2024; the RELEASE-authoritative marker is `BasicFileInfo` `Format:` (what `rvt.versions.detect_release` keys on).  A 2024 writer writes 2662 unchanged.
* `Global/ElemTable` lead class tag: 2024 `0x583` vs 2025 `0x5ab` vs 2026 `0x5c9` (= `ElemTable` -- an ordinal, resolved by name)
* `ElemTable` footer tail class: 2024 `0x901` vs 2025 `0x93b` vs 2026 `0x96a` (= `IdentifierSource`)
* `Global/History` lead class tag: 2024 `0x4ff` vs 2025 `0x51d` vs 2026 `0x538`

These stream-lead tags round-trip automatically through the decoders (they preserve the decoded `class_tag`); only a from-scratch 2024 stream author needs the table above.

## 6. The module-local baked-tag patch set (unchanged from 2025)

`rvt.versions.reading` patches `rvt.partitions`; the emit path keeps module-LOCAL copies of the framing ordinals that the patch cannot reach.  The SEVEN-entry patch set genesis_2025 proved complete (2025 ladder viewer-certified, verdicts #28) is re-used verbatim by `tools/genesis_2024.py::release_context` -- nothing in it is release-specific (every value derives from the active ordinals):

| module | attr | why |
|---|---|---|
| `rvt.reduce` | `BLOCK_TAG` (local literal 0x0F28) | `NewBlock.frame` writes block headers |
| `rvt.reduce` | `BLOCK_TRL_TAG` (from-import) | block trailer mirror |
| `rvt.manipulate` | `BLOCK_TAG`, `TRAILER_TAG` (from-imports) | the modify path re-frames blocks |
| `rvt.commit` | `BLOCK_TRL_TAG` (from-import) | commit re-frames touched blocks |
| `rvt.writer` | `BLOCK_TRL_TAG` (module constant) | reframe_blocks |
| `rvt.famgen.factory` | `CD_SEPARATOR`, `CD_END_RECORD` (bake 0x3A3/0x3A2) | ContentDocuments grammar (2024: 0x37B/0x37A) |
| `rvt.adocument` | `_DECODER` (cached 2026-schema decoder) | ADocument decode/encode must use the file's schema |

Proposed permanent fix (versions stream / orchestrator, unchanged from the 2025 record): fold these into `rvt.versions.activate` so `reading()` covers the emit path too; until then `genesis_2024.release_context` / `genesis_2025.context_2025` are the working recipes.
