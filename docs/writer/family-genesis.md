# FAMILY-GENESIS — the ADocument codec at the family level, and the retired
# partition unit footer / stream end record  (TRACKER G4b)

Module: `src/rvt/famgen/famdoc_adoc.py` · tests: `tests/test_famgen_adoc.py` ·
deliverables: `experiments/families/genesis2/` · record:
`docs/inbox/family-genesis.md`.

## Why this stream exists

The asset assay (`docs/inbox/asset-assay.md`) established that every
generated `.rfa`'s ELEMENT layer is genuinely constructed (0 records
byte-identical to any specimen, no ballast, no GUID reuse) — but each
container still carried three donor / opaque artefacts:

1. `Global/Latest` — the DONOR table family's serialized ADocument,
   byte-for-byte (68,508 B raw, 1.38 MB inflated, ~25 % of the non-format
   bytes), whose registries reference **1,727 dangling ids** of donor
   elements that do not exist in our file.
2. The partition unit footer + end record — copied opaquely from the donor
   ("the literal string *Data generated by Autodesk* at tail −257 of
   `Partitions/0`").
3. The four `G_*` geometry proofs — Autodesk's whole sample container
   (employee Windows path, "Author: Autodesk Revit", their thumbnail).

This stream retires all three by CONSTRUCTION, applying the genesis-2
discipline (`tools/genesis_assemble.py`: schema-typed PURGE, coherence,
cache-emptying, REPOPULATION over OUR inventory, our authorship, re-encode /
re-decode / equality gates) at family scale — and, along the way, fully
DECODES the partition footer / end-record grammar the corpus had marked
`[undecoded]`.

## Part 1 — the family document's ADocument, constructed

### The family-document ADocument shape (verified, archetype = the 2026 sample family)

The archetype's `Global/Latest` decodes clean and re-encodes byte-exact
with the **unchanged** `rvt.adocument` codec (the same one that is byte-exact
on all six project samples). A family document's ADocument differs from a
project's only in scale and a handful of members:

| member | family document | project document |
|---|---|---|
| `AppInfoManager.m_appInfoArr` | **239** slots | 241 slots |
| slot classes | identical class at every index (130/130 populated slots agree with the project table); slot 10 = `SectionNaming` (family-only) | slot 10 unused |
| `m_ownerFamilyId` | the owning **self-`Family`** element (17 in the archetype) | −1 |
| `m_pPartitionTable` | null (no worksets) | null ptr → `Global/PartitionTable` |
| bytes | 96.5 % = `ESSchemaStorage` Forge corpus (see below) | idem |
| id-carrying registries | index the DATUM / VIEW / SETTINGS layer only | idem |
| positional `UniqueElementsTracking` | the SAME compiled-in table, 93 slots (14/15 archetype positions agree with the project-derived map; pos 85 `DrawOrder3dElem` merely never appears in the project samples) | 72 populated slots |

What the family registries index (attributed by decoding the archetype's
own elements): `DatumTracking` = Level + RefPlanes;
`ElementTrackingData.m_elems` = RefPlane→OST −2000530, Level→−2000240,

**Not indexed by any registry** (verified against the archetype's own

## Part 2 — the partition footer + end record, DECODED (counsel C5)

Corpus proof: `footer_forensics()` → `experiments/families/genesis2/
footer_forensics.json` — **2,072 genuine units across the six project
samples + the family archetype**.

Grammar of a unit's close, after its last block:

```
unit terminator   u16 0x0f28 + 16 zero bytes                              FORMAT
footer blob       u16 0x0f3f + u32 n + n bytes  (n = 64, or 0)             tag+n: FORMAT
                                                                            bytes: PER-UNIT NONCE
footer string     u32 34 (char count) + UTF-16LE
                  "Data generated by Autodesk® Revit®"   (72 bytes)         FORMAT SIGNATURE
end record        u16 0x3a3 + i32 0 + i32 -1   (10 bytes = a30300000000ffffffff)
                                                                            FORMAT CONSTANT
[ + the final block's CRCIO pad-count + parity = on-disk framing, NOT content ]
```

Findings:

* **The signature string is universal.** Byte-identical
  (`44 61 74 61 …` UTF-16LE, u32 count 34) in **2,072 / 2,073 units** of
  every file inspected; the 2,073rd is the degenerate EMPTY form (n = 0) in
  the tiny `dach` `Partitions/85`. It is a required **format signature** —
  the analogue of a file magic — not donor expression. Counsel C5's answer:
  an **irreducible format token**; we write it ourselves from the
  `DATA_GENERATED_STRING` constant `rvt.famgen.skeleton` already owns (it
  was never copied bytes). Its exact wire bytes, offset (immediately after
  the tagged blob) and universality are frozen in `FOOTER_TOKENS`.
* **The 64-byte blob is a per-unit opaque nonce.** 2,071 distinct / 2,071
  genuine units; entropy 7.885–7.926 bits/byte at every one of the 64
  positions (8.0 = uniform random); zero constant positions; no standard
  digest (SHA-512/384/256, SHA-3, BLAKE2, MD5, SHA-1) of any candidate
  content span (gzip members, inflated records, the unit span, the whole
  stream) matches; not RFC-4122 GUIDs. Its VALUE is **not reader-verified**:
  every re-blocked reduction that LOADED (R5/R9/K1) kept a stale blob, the
  `dach` unit and our proven-loading L1a save units carry the **0-length**
  form. `build_footer()` therefore supplies OUR value — a deterministic
  64-byte digest of our own document identity (or the empty form) — and
  the file carries **zero donor footer bytes**. (Our factory `.rfa` had
  duplicated the donor's blob byte-for-byte — the one blob duplicate the
  census found.)
* **The end record is a 10-byte universal constant** —
  `a3 03 00 00 00 00 ff ff ff ff` (u16 0x3a3, i32 0, i32 −1), identical in
  **8 / 8** exactly-unframed streams (the empty-form `dach` unit
  included). The 48–276-byte *"opaque high-entropy tail"* the corpus (and
  the `rvt.partitions` docstring) recorded as `[undecoded]` is **not
  content**: it is the CRCIO pad-count + parity of the stream's **final
  block**, mis-attributed because `container.depage` leaves the final
  partial page's trailer as trailing junk. Proved: `ecc.unframe_stream`
  is byte-exact (re-frame == the on-disk stream) on **every** file; the
  archetype's 92-byte "end record" == the 10-byte constant + 82 bytes ==
  its own on-disk final-block parity. Consequence: every
  `emit_family_rfa` output carried **82 bytes of the donor's stale ECC
  parity as junk content** inside our logical stream. `FAMILY_END_RECORD`
  retires it. This DECODE retires the `partitions.py` `[undecoded]` note —
  a request for that module's owner is on record.

## Part 3 — the clean emission path (`emit_family_rfa_v2`)

A famgen-side wrapper (no `skeleton` / `factory` edit — the assembler's
`footer_blob` / `end_record` parameters were already the injection points).
Versus `skeleton.emit_family_rfa`:

| stream | before (factory) | v2 |
|---|---|---|
| `Global/Latest` | the donor's ADocument (68,508 B raw) | OUR authored family ADocument |
| unit footer blob | the donor's 64 bytes | ours (nonce) / the empty form |
| end record | the donor's 92-byte junk (10-byte constant + 82 B stale parity) | the DECODED 10-byte constant |
| Global stream prefixes | read off the donor container | the `GLOBAL_STREAM_PREFIX` constants |
| `Contents` prologue | encoder, donor fallback | OUR encoder |
| `BasicFileInfo` / DIT | our identity via the genesis skeleton | our identity **through `rvt.identity`** (`own_identity_model` + `own_increment_table_payload`), cross-stream GUID invariants preserved |
| `Formats/Latest` | carried | carried — the ONE remaining donor read, sha256-checked as the Revit-2026 corpus schema constant |

Every emitted file: read-back verified (gzip CRC, CRCIO ECC, walker,
per-seq record counts, schema decode) + the certified validator in family
mode + `provenance_scan_v2`.

### Validation, honestly labelled

The certified `rvt.validate` has no family mode (its calibration is
project-shaped: it requires `ProjectInformation` and CRCIO framing of every
stream, but a family's `PartAtom` is plain unframed Atom XML). Two verdicts
are reported for every v2 file:

* **family mode** (the two family-shape adjustments; everything else —
  container, ECC, gzip, walker, schema decode, table decodes, reference
  integrity — unchanged): **VALID, 0 errors, 0 warnings** on every v2 file.
* **arbiter raw**: 3 residual findings (`ProjectInformation` missing +
  the two `PartAtom` framing findings) — and the calibration control: the
  **authentic Autodesk donor `.rfa` scores WORSE**, 5 raw errors and even
  2 family-mode errors (its ElemTable graveyard + DIT don't decode with our
  decoders). The residual findings are family-shape calibration gaps, not
  defects. The asset assay's request to merge the family-mode adjustments
  as a certified `rvt_validate --family` mode is re-raised (validate.py is
  not this stream's territory).
