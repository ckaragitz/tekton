# Content-document (save-unit) removal — the discrepancy audit and the corrected recipe

Stream: **genesis-triage-b (BUG B)**, 2026-08-03.  Module: `src/rvt/reduce_v2.py`
(`remove_units_v2`, `verify_content_coherence`, `python -m rvt.reduce_v2 --probes|--diff`).
Subject: the ladder-v2 unit-removal path (`tools/rvt_reduce.py::remove_units` →
R9b/R10b, validator-VALID, reader **FAIL**) diffed field-by-field against the
SOLVED `Global/ContentDocuments` grammar (`rvt.famgen.factory`, asset-forge)
and the ECC-exact stream framing.  Every number below was measured this
session on `experiments/genesis/{R9,R9b,R10b}.rvt` + `samples/*.rvt`;
reproduce with `python -m rvt.reduce_v2 --diff`.

## 0. Verdict in one paragraph

**The literal Bug B hypothesis — "the ContentDocuments splice is malformed
against the solved grammar" — is FALSE at the byte level**: the OLD path's
`Global/ContentDocuments` output is **byte-identical** to the solved-grammar
rebuild for the same GUID set (`assemble(parse(R9) − 38 removed) == R9b's CD
payload`, 320,897 B; separators, GUID sort order, per-entry `u32` lengths and
mirrors, the 14-byte end record and the `u64 1` stream prefix all identical —
the wave-1 marker scanner's entry boundaries happen to coincide with the
grammar on this corpus).  The unit splice inside `Partitions/21` is likewise
byte-clean and correctly counted.  The reader-visible discrepancies between
the FAILING R9b/R10b and the PASSING R9 are exactly TWO, both outside the CD
grammar: **(D1)** `Global/Latest`'s two content registries — `ContentTable
.m_ContentRecSet` and `FamilyMgr.m_arrLoadedFamilyInfo`, the ONLY two sites a
content GUID occupies in the ADocument — still name all 38 removed documents
(the coherence rule of audit verdict #3, violated); and **(D2)** a hitherto
unlogged framing defect: the old path writes the parent generation's de-paged
ECC pad-count + parity bytes as **stream content after the partition end
record**, so second-generation files carry a growing junk tail (R9b **294 B**,
R10b **506 B** after the 10-byte end record) where Autodesk's own logical
stream ends **at** the end record (0 B; ECC-exact on all six samples).  The
corrected recipe rebuilds all three streams from the model and probes B1–B5
isolate D1 vs D2 as a byte-exact 2×2 factorial.

## 1. The four wire objects a unit removal touches (grammar, with offsets)

### 1.1 `Partitions/<N>` — save units (removal = splice)
```
logical = header(18) unit0 unit1 … unitK end_record
header  @0     : u32 9, u32 0, u16 0x3a3, i32 0, u32 elem_table_count   (18 B)
unit 0  @18    : blocks + terminator(18) + 0x0f3f footer(64-B blob)
                 + u32 n + UTF-16 'Data generated by Autodesk® Revit®'
unit k>=1      : SEPARATOR(28) + blocks + terminator + footer + magic
  separator    : u16 0x3a3 | i32 -1 | u16 0x3a2 | u32 counter | GUID(16, bytes_le)
                 e.g. R9 unit 36 @1,938,257: a303 ffffffff a203 a1010000
                 bb2d980922c0fc48a1166d8ba6867fdb  (counter 0x1a1 = 417 =
                 the unit's REAL record count, sentinel excluded; verified
                 counter == records−1(sentinel) on all 52 rst units)
end_record     : u16 0x3a3 | i32 0 | i32 -1  = a303 00000000 ffffffff  (10 B)
                 THE AUTODESK LOGICAL STREAM ENDS HERE — verified by
                 rvt.reduce.unframe_exact (ECC pad-count decode) on all six
                 samples; the "u32 0 + zero pad + high-entropy tail" of older
                 notes is the final CRCIO block's pad+parity, not content.
```
Unit ranges tile `[18, end_offset)` — unit k spans from ITS separator to the
next separator — so any subset splices out losslessly (`_unit_ranges` /
`reduce_v2.unit_ranges`; tiling asserted).

### 1.2 `Global/ContentDocuments` — one entry per embedded document (SOLVED grammar)
```
stream logical : u64 1 prefix (per-stream-name constant) + gzip(payload)
payload        : entry* + END_RECORD
entry          : SEP(12: a303 ffffffff a203 ffffffff)     # u16 0x3a3,i32 -1,u16 0x3a2,i32 -1
                 + GUID(16, bytes_le)  + u32 adoc_len + ADocument(adoc_len)
                 + u32 adoc_len (mirror)                  # entries GUID-sorted (bytes_le memcmp)
END_RECORD     : a303 00000000 ffffffff 00000000            # u16 0x3a3,i32 0,i32 -1,u32 0 (14 B)
rst/R9         : 52 entries, payload 1,365,825 B; first entry @0
                 (a303ffffffffa203ffffffff 00100678a3568c42a5a85b1397dbb12d
                  4c4d0000 = adoc_len 19,788); last 14 B = END_RECORD.
```
There is NO in-payload count or prologue; the map is a self-tiling array
(entry k+1 begins where entry k's mirror ends).  Removal = drop whole entries,
keep the end record — `factory.parse/assemble_content_documents`.

### 1.3 `Global/Latest` — the ADocument's two content registries (COHERENCE)
```
ADocument.m_oContentTable.value.m_ContentRecSet[i]            # 52 records (rst/R9)
    .m_ContentKey.m_guidKey  == a save-unit / CD GUID
    .m_author 'Autodesk Revit', .m_history{episodes}, .m_EpisodeCounts[]
ADocument.m_pAppInfoManager.value.m_appInfoArr[0] = FamilyMgr # slot 0
    .m_arrLoadedFamilyInfo[j] = { m_surrogateId (host id),
                                  m_familyDocGUIDs [GUID …] }  # 50 entries:
                                  41 non-empty carry all 52 GUIDs
                                  (34 single + 7 multi = 34+18),
                                  9 empty (system/in-place families)
```
Measured: **every one of the 52 content GUIDs occurs EXACTLY TWICE in R9's
ADocument** (1× ContentTable, 1× FamilyMgr); the embedded documents' 14,052
element ids occur **0 times** as i64 windows anywhere in `Global/Latest`
(no id registry to reconcile — only the two GUID sites).

### 1.4 `Global/PartitionTable` — NOT INVOLVED
`Global/PartitionTable` is the **workset table** (`u16 0x0c80, u32 version 1,
u32 count 1` + one 'Workset1' row, 134 B logical), **byte-identical in rst,
R9, R9b**.  There are no per-save-unit rows to drop; the charter's
"PartitionTable rows" premise conflates worksets with save units.  A unit
removal never touches this stream.

## 3. THE CORRECTED RECIPE — `remove_units_v2(doc, guids)`

From a base project and a set of save-unit GUIDs (== ContentDocuments keys):

1. **`Partitions/<N>`** — recover the EXACT logical stream
   (`rvt.reduce.unframe_exact`: final CRCIO block's data length from its
   pad-count field; NOT `RvtDocument.logical()`), splice the removed unit
   ranges out (ranges tile `[18, end_offset)`), and terminate with the
   canonical 10-byte end record `a30300000000ffffffff` (`exact_tail=True`;
   `False` byte-preserves the base's own tail for one-variable probes).
   Re-frame with real CRCIO ECC (`rvt.ecc.frame_stream`).
2. **`Global/ContentDocuments`** — re-BUILD by the solved grammar
   (`rebuild_content_documents`): parse → drop the GUIDs → `assemble`
   (GUID-sorted, u32 length + mirror, 14-byte end record) → `u64 1` prefix +
   gzip level 3 → frame.  Never edit in place.
3. **`Global/Latest`** — decode (`rvt.adocument`, byte-exact codec gate) →
   `reconcile_content_registry`: drop the `ContentTable.m_ContentRecSet`
   records keyed by the removed GUIDs AND remove the GUIDs from every
   `FamilyMgr.m_arrLoadedFamilyInfo[].m_familyDocGUIDs` (entries whose list
   empties are dropped) → re-encode → frame.  (`reconcile_adocument=False`
   is the coherence-isolation switch — probe B4.)
4. **`Global/PartitionTable`** — untouched (workset table).
5. Write the container (`rvt.cfb_writer.write_cfb`).
6. Post-condition (`verify_content_coherence`): partition unit GUIDs ==
   CD entry GUIDs == ContentTable GUIDs == FamilyMgr GUIDs, partition tail
   junk == 0, CD end record + grammar round-trip OK.  All B-probes and the
   test suite assert it.

Nested-document rule (from the ladder): a KEPT parent document must not name a
removed nested child (`Family.m_oFamDoc.m_contentDocGUID` inside another
unit); the R9b removal set already respects it, and `remove_units_v2` removes
exactly the GUIDs it is given (the CALLER closes over nested children —
`tools/rvt_reduce.run_stage_r9b`'s fixpoint, or `family_units()` for lookup).
