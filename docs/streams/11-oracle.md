# 11 — Ground-truth oracle: `.rvt` decode vs Revit's own IFC export

Wave 2, agent `oracle-harness`. Tools: `tests/oracle/` (README there).
Everything below is machine-checked; the report tables are the verbatim
output of `compare_oracle.py` / `schema_drift.py` (2026-08-02).

## Why this matters

Until now every element-layer claim (which class_word is a Wall, what a
Level record looks like) was inference. `magnetar-io/revit-test-datasets`
ships real Revit files WITH matching exports of the same models, so we can
now **measure** the decode: Revit's IFC exporter stamps every element with
its Revit **ElementId** (`IfcElement.Tag`, and again in `Name` =
`Family:Type:Id`) and stamps the file with the document's episode GUID
(`FILE_DESCRIPTION ... VersionGUID`). That gives a per-element ground truth
that joins straight onto our partition-record index. `pytest tests/oracle`
pins the agreement so decoder work is a scored loop, not a guess.

## Finding 1 — the storage/framing layer is release-independent when keyed BY CLASS NAME

De-paging (64,896 + 353) applies unchanged to 2023 and 2024: **every**
gzip member CRC-verifies (Einhoven 58 blocks + 9 global streams, Core
Interior 1,644 blocks). The Partitions framing is byte-identical in
structure across 2023/2024/2026; ONLY the u16 tag values differ — and each
tag equals a class id in that file's own `Formats/Latest`:

| framing role | class name (schema) | 2023 | 2024 | 2026 |
|---|---|---:|---:|---:|
| stream header / unit separator / end record | `ContentMarker` | 0x365 | 0x37b | 0x3a3 |
| separator inner class | `ContentKey` | 0x364 | 0x37a | 0x3a2 |
| block header + unit terminator | `SegmentMarker` | 0xe4e | 0xe7c | 0xf28 |
| block trailer | `SegmentCheckback` | 0xe47 | 0xe75 | 0xf21 |
| unit footer 64-byte blob | `SignatureMarker` | 0xe61 | 0xe8f | 0xf3f |
| seq101 record class | `ElementHeader` | 0x576 | 0x59f | 0x5e5 |
| seq103 record classes | `SerializedDummy` / `GElement` | 0xe52 / 0x819 | 0xe80 / 0x83f | 0xf2c / 0x89e |
| Global stream leads | `ADocument` 0x1c (all), `ElemTable` | 0x55a | 0x583 | 0x5c9 |

`tests/oracle/rvt_release.py` therefore resolves all framing tags **by
name** from the file's own schema instead of hard-coding 2026 constants, and
walks any release: 100 % blocks CRC-valid, 100 % record-walk coverage on all
three (Einhoven 5,282 objects, Core Interior 50,728, racbasic 8,401 —
zero framing errors). **This confirms the KNOWLEDGE claim that our type id
(definition order + 0x0c) is exactly the on-disk class word** — every
framing tag above landed on the semantically right name (`SegmentMarker`
frames segments, `SignatureMarker` precedes the "Data generated by
Autodesk® Revit®" signature, `ContentMarker`/`ContentKey` frame content
units) in three independent releases.

### Release-dependent record layouts (new, from the old files)

| item | Revit ≤ 2023 | Revit ≥ 2024 |
|---|---|---|
| ElementId width | **32-bit** (`u32`) | **64-bit** (`i64`) — matches the public 2024 API change to `ElementId` (`long`) |
| seq101 record header | `{u32 id, u32 body, u32 cls}` = 12 B | `{i64 id, u32 body, u32 cls}` = 16 B |
| seq102/103 record header | `{u32 id, u32 stamp, u32 body, u32 cls}` = 16 B | `{i64 id, u32 stamp, u32 body, u32 cls}` = 20 B |
| `Global/ElemTable` record | 28 B: `{u32 orig, u32 id, u32 create_ep, u32 mod_ep, u32 user_ep, u32 part, i32 owner}` | 40 B: `{u64 orig, u32 create_ep, u32 mod_ep, u32 user_ep, u64 id, i64 owner, u32 part}` |
| Partitions header u32[4] | element count **of that partition** (Einhoven /0=2,520, /5=66 … ≠ ElemTable total 2,615) | same field (Core Interior /46=20,156 … sum ≠ ElemTable 26,425); it equalled `Global/ElemTable` count in our 2026 samples only because each had ONE partition |

`oracle_extract.py` auto-detects both layouts (the one that walks 100 % of
the segment wins); id width is reported per file.

## Finding 2 — the wave-1 schema grammar is release-independent (`schema_drift.py`)

```
release  build                   schema bytes  classes  fields   parsed  desync at class
2023     20230828_1515(x64)           462,765    4,140  11,208   94.8%  VarExpr.m_refCt
2024     20230509_0315(x64)           470,502    4,195  11,284   94.6%  VarExpr.m_refCt
2026     20250227_1515(x64)           496,597    4,386  11,845   94.7%  VarExpr.m_refCt
```

`src/rvt/schema_a.parse()` (never touched a pre-2026 blob before) parses
4,140 / 4,195 / 4,386 classes and stops at the **same** class
(`VarExpr.m_refCt`, descriptor bytes `04 00 04 00` — a kind-4 tag with a
non-zero pad word the grammar has no rule for) in every release: the ~5 %
tail is one grammar gap, not per-release corruption. Fixing that single
rule finishes the class map for all releases (see inbox).

Pairwise: 2023→2024 4,115 shared class names (99 %), 2024→2026 4,163 (99 %);
ids drift by a class-dependent offset (median +41 for 2023→2024, +95 for
2024→2026; range up to ±3,700 because inline definitions shift), with only
2–5 % of ids identical. **Decode by class NAME, never by numeric id.**

Name-keyed drift for format-relevant classes (our id == on-disk class word):

| class | 2023 | 2024 | 2026 |
|---|---:|---:|---:|
| ADocument / Element / A3PartyAImage | 0x1c / 0x25 / 0x0c | same | same |
| ElementHeader / ElemTable / ElemRec | 0x576 / 0x55a / 0x556 | 0x59f / 0x583 / 0x57f | 0x5e5 / 0x5c9 / 0x5c5 |
| DocumentHistory / DocumentIncrementTable | 0x4dc / 0x4e0 | 0x4ff / 0x503 | 0x538 / 0x53c |
| SWall / Level / Grid / Floor | 0xe29 / 0x949 / 0x881 / 0x7bb | 0xe55 / 0x976 / 0x8ad / 0x7e1 | 0xf02 / 0x9e7 / 0x90e / 0x83f |
| FamilyInstance / FamilySymbol / Family / FamilySurrogate | 0x740 / 0x762 / 0x72a / 0x75f | 0x766 / 0x788 / 0x750 / 0x785 | 0x7c5 / 0x7e6 / 0x7af / 0x7e3 |
| BasicWallType / FloorAttributes / RoofAttributes / RoomElem | 0x22b / 0x7bd / 0xdde / 0xdf1 | 0x23e / 0x7e3 / 0xe09 / 0xe1c | 0x25b / 0x841 / 0xeb5 / 0xec8 |
| CurtainGridLine / SysPanelFamSym / SiteSurface | 0x3bf / 0xfb2 / 0xe71 | 0x3d8 / 0xfe2 / 0xe9f | 0x404 / 0x1097 / 0xf4f |
| PartitionTable / GStyleElem / CategoryElem / CurveElem | 0xbc0 / 0x845 / 0x2ab / 0x37c | 0xbec / 0x86d / 0x2be / 0x392 | 0xc80 / 0x8cc / 0x2e1 / 0x3ba |

**rvt-rs's `tag-drift-2016-2026.csv` validated with a caveat:** all 219
comparable cells (their 122 classes × 2023/2024/2026 columns) equal **our
id + 1**, i.e. rvt-rs's "tag" is systematically one higher than the class
word that actually appears on disk (they scan the raw u16 after each class
name with 0x8000 masked; we number definitions from 0x0c). On-disk
evidence — `ContentMarker` in the Partitions header, `SegmentMarker` on
every block, `ElementHeader` on every seq101 record — matches OUR value in
all three releases, so their table needs a −1 to be used as class words.
Their 64 KiB scan cap also limits it to 122 classes vs our 4,100+.

## Agreement report — pair B: `Revit_IFC5_Einhoven.rvt` (Revit 2023) ↔ FME/StrangeMatter exports

No IFC of the Einhoven model exists in the dataset; the FME CSVs are the
oracle. Their `SourceDataItemId` = Revit UniqueId = episode GUID + 8-hex
ElementId. Result: **26 distinct ElementIds → 26/26 in `Global/ElemTable`
(28-byte 32-bit records) and 26/26 as seq102 object records**; all three
episode GUIDs seen (`4010f260…`, `d8627339…`, `df1e0839…`) are entries in
the rvt's `Global/History`.

| FME classification | n | rvt record class | example ids |
|---|---:|---|---|
| `hok.wall.Properties` | 1 | **SWall** | 2808 (0xaf8, the host curtain wall) |
| `hok.wall.curtainpanle,properties` | 24 | **FamilyInstance** | 7197, 7290 … 8686 (curtain panels) |
| `ifc.window.casement` | 1 | **FamilyInstance** | 5317 (0x14c5, hosted window) |

So curtain panels serialize as `FamilyInstance` (not `SysPanel`) in 2023
too, and the 32-bit-id / 28-byte-ElemRec / 12+16-byte record-header layouts
are confirmed by an external oracle, not just by walk statistics.

## Confidence & scope of the confirmed decode

CONFIRMED (per-element ground truth, N shown): SWall (360), FamilyInstance
(394 doors/windows/columns + 24 Einhoven panels), Floor (99), Level (15
named), BasicWallType (4), FamilySymbol/Family/FamilySurrogate (12 types),

must be characterised by the object decoder, not by this oracle.

## Unknowns

* The u32 in the Partitions stream header is the **partition's own element
  count**, not the ElemTable total — the mapping partition N ↔ elements
  (worksharing worksets vs. document increments) is unresolved for the
  multi-partition 2023/2024 files. `[open]`
* Why seq102 raw record counts exceed distinct ids by ~2× in `Partitions/46`
  (superseded versions kept per save unit) — needs the object decoder to
  confirm "last record wins". `[hypothesis, consistent with all joins]`
* The IfcSpace ↔ RoomElem attribution is by name (numbers/names inside the
  RoomElem body); the room's ElementId is not in the IFC (IfcSpace has no
  Tag), so it is CONFIRMED-by-name, not by id join.
* Curtain walls: the Einhoven wall 2808 is a curtain wall yet its record
  class is `SWall` (panels are FamilyInstance, grid lines
  `CurtainGridLine`); Core Interior has 5,112 `CurtainGridLine` records but
  no IfcCurtainWall in the export → curtain-wall decomposition unverified.
* `Wall`, `TopographySurface`, `PanelBoard`, `MEPCurve` are NOT class names
  in the serialized schema (Revit's C++ names: `SWall`, `SiteSurface`,
  `FamilyInstance`, `RbsCurve…`); the schema tail after the `VarExpr`
  desync (~5 %) is unparsed in every release, so a few electrical classes
  may still be hiding there. `[open, schema agent]`
